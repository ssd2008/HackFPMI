# Проверка почтового поиска на всех подготовленных данных

Для сравнения взяли работавшую до этого раунда версию `a211900`. Качество измеряли по десяти первым письмам. Требование организаторов к скорости — серверный p99 строго меньше 1 000 мс. Время включает разбор запроса, отбор писем, ранжирование и подготовку выдачи. В комплекте открытых данных для локальной проверки предложены Recall, nDCG и MRR. Закрытых оценок организаторов у команды нет. [Условие](../data/vk-mail-search.pdf) · [Описание публичных данных](../data/README.md)

## Что изменилось в поиске

- Отправителя, адрес и тему движок извлекает из заголовков письма. Для явного условия ищет совпадение в соответствующем поле. Отдельно обрабатывает вложенные кавычки и склонение названия в русской фразе. Просьба найти дословную цитату сохраняет точное сопоставление. Это устранило группу пропусков, где одно и то же название стояло в разных падежах.
- Номер целиком получает приоритет над вхождением внутри другого слова. При поиске события движок различает его подтверждение и документ о подготовке. Так извещение о состоявшейся погрузке поднялось выше предварительного разрешения. При прямом запросе о разрешении оно сохраняет свой вес.
- Морфология и BM25 работают со списками писем для каждого слова. При поиске склоняемой фразы движок сначала проверяет, встречается ли в письме самая длинная обязательная основа слова. Только после этого он сопоставляет фразу целиком. Это сократило время самых медленных запросов в личной почте. Для естественного вопроса по обычному текстовому архиву увеличен вес многоязычной модели E5. Даты событий в справочном вопросе, даты получения писем и периоды начислений обрабатываются отдельно. [Многоязычная E5](https://arxiv.org/abs/2402.05672) · [Обзор методов команды](vk_mail_search_methods.md)
- Русский запрос может найти английское письмо по локальному двуязычному словарю. Для обычной темы учитываются переводы значимых слов и их близость в тексте, затем проверяется смысловое сходство. Для вопроса о количестве в небольшом временном окне учитываются число, единица и операция в одной фразе. Например, начисление и списание одной и той же единицы ведут к разным письмам. [Источник словаря, лицензия и сборка](../mailsearch/resources/FREEDICT.md)

## Какие ошибки остались

В четырёх почтовых выборках **7 936 основных задач и 7 034 варианта формулировок**. Среди 6 285 положительных задач полных пропусков стало **4 вместо 70**. Среди 1 651 проверенной пустой задачи осталось **9 ложных непустых выдач вместо 30**. Есть и неполные выдачи, где часть нужных писем оказалась ниже десятого места. Все дополнительные ящики использованы при разработке и повторной проверке. Для новой слепой оценки нужны свежие задачи.

У трёх пустых задач VK обнаружилось расхождение с разметкой. В четырёх возвращённых письмах номер действительно встречается в нужном ящике к указанной дате. В тексте он слит с соседней буквой, а авторское правило распознаёт номер по границам слова. В сводных оценках оставлены исходные метки и все три ошибки. Ещё шесть ложных непустых выдач относятся к личной почте. Все 56 отдельных пар про неизвестную дату и условную отмену прошли обе части проверки. [Полный почтовый прогон](../results/ood_round4_mail.json) · [112 запросов для пар условий](../results/ood_round4_events.json)

Проверили также многоязычный cross-encoder mMARCO MiniLM как способ восстанавливать пустую выдачу. На 57 вручную размеченных задачах с небольшим временным окном модель ставила правильное письмо первым в четырёх из пяти пропусков текущего на момент эксперимента поиска. Три из пяти проверенных пустых задач тоже получили высокий балл. Медианное время повторного ранжирования составило около 146 мс на этом Mac. Для этой версии оставили проверку слов и фактов в письме. [Модель и её назначение](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)

## Ответы со ссылками

На 388 заданиях RAG было **308 вопросов с ответом и 80 случаев с недостаточными сведениями**. Предыдущая версия последовательно дала 299 полных ответов и 76 обоснованных отказов. Обновлённая версия дала **308 и 80**. Все 605 обязательных фактов подтверждены ссылкой на нужный оригинал. При восьми одновременных клиентах сохранились и результат каждой задачи, и порядок источников. Поиск и генерация используют разные HTTP-методы, поэтому в показатель p99 поиска входит только работа до выдачи писем. [Разработочные ящики](../results/ood_round4_rag.json) · [Дополнительные ящики](../results/ood_round4_rag_holdout.json)

## Как повторить

Для одиночного запуска из каталога проекта используйте `./run.sh --port 8766` и откройте [локальную почту](http://localhost:8766/). На чистой машине сначала загрузятся модели. В обычном поиске используются локальные веса и индекс. На проверенной версии прошёл 81 автоматический тест. В Chrome проверили выбор ящика и даты, поиск, ответ с суммой и переход к письму с этой суммой, а также повтор пустого поиска без кавычек.

Для сравнения двух версий создайте отдельные рабочие копии Git. Контрольный поиск и генерация в `b5252c1` и `a211900` побайтно совпадают, поэтому для внешних наборов использована уже проверенная контрольная выдача `b5252c1`. Для каждой версии запустите по одному серверу на каждом из двух почтовых корпусов из комплекта. Файл `documents.jsonl` побайтно одинаков у `dev` и `holdout` внутри источника. Сохраните пути к проверочному комплекту и к окружению Python. Пример ниже использует те же обозначения портов, что и отчёт.

```sh
export POOL="/путь/к/HackFPMI-mail-OOD"
export PYTHON_BIN="$PWD/.venv/bin/python"
export BASE_REV=a211900
export SEARCH_REV=d18d1a0
git fetch origin codex/ood-validation-pool
git worktree add --detach .cache/compare-before "$BASE_REV"
git worktree add --detach .cache/compare-after "$SEARCH_REV"

(cd .cache/compare-before && "$PYTHON_BIN" -m mailsearch --data "$POOL/suite/vk_dev" --port 18810) &
(cd .cache/compare-before && "$PYTHON_BIN" -m mailsearch --data "$POOL/suite/personal_dev" --port 18811) &
(cd .cache/compare-after && "$PYTHON_BIN" -m mailsearch --data "$POOL/suite/vk_dev" --port 18822) &
(cd .cache/compare-after && "$PYTHON_BIN" -m mailsearch --data "$POOL/suite/personal_dev" --port 18823) &
```

После появления `/api/mailboxes` на всех четырёх адресах запустите полную почтовую проверку. Затем отдельно измерьте задержку на машине без одновременных прогонов RAG или внешнего поиска.

```sh
"$PYTHON_BIN" tools/check_mail_ood.py --pool "$POOL" --split all --run \
  --runs .cache/compare-mail --output .cache/compare-mail.json \
  --baseline-revision "$BASE_REV" --candidate-revision "$SEARCH_REV" \
  --vk-dev-before http://127.0.0.1:18810 --vk-dev-after http://127.0.0.1:18822 \
  --personal-dev-before http://127.0.0.1:18811 --personal-dev-after http://127.0.0.1:18823
"$PYTHON_BIN" tools/check_four_metrics.py --pool "$POOL" --include-holdout \
  --before-revision "$BASE_REV" --after-revision "$SEARCH_REV" \
  --vk-before http://127.0.0.1:18810 --vk-after http://127.0.0.1:18822 \
  --personal-before http://127.0.0.1:18811 --personal-after http://127.0.0.1:18823 \
  --clients 1 8 --pairs 2 --min-samples 1000 --output .cache/compare-four.json
```

Проверка сверяет контрольные суммы корпусов и меток. При измерении p99 версии получают одни и те же перемешанные запросы в чередующемся порядке. Во время каждого обращения сервер выполняет реальный поиск. Протокол сохраняет p50, p95, p99 по серверному таймеру и полное время HTTP на localhost. Файлы с личными текстами и выдачами остаются в локальном каталоге `.cache`.
