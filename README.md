# Конверт · умный поиск в почте

Локальный прототип для кейса VK на хакатоне Студсовета ФПМИ. В интерфейсе можно открыть любой из 12 учебных ящиков, найти письма обычным русским запросом и получить ответ с переходом к оригиналу. В этом файле собраны контекст задачи, инженерные решения и воспроизводимые проверки.

## Запуск

Запустите сервис из корня проекта на macOS или Linux.

```sh
./run.sh
```

Откройте [почту на localhost](http://localhost:8765/). Скрипт использует `uv` или установленный Python 3.12, ставит зависимости в `.venv` и проверяет наличие моделей. На чистой машине понадобится интернет для установки библиотек и загрузки около 3,7 ГБ весов с Hugging Face. Индекс писем строится автоматически и сохраняется между запусками. Сервер привязан к `127.0.0.1`. Для другого порта используйте `./run.sh --port 8766`, для остановки в терминале нажмите Ctrl+C.

В подготовленном окружении данные можно проверить отдельно и запустить сервер с локальными весами.

```sh
.venv/bin/python -m mailsearch.prepare --offline
.venv/bin/python -m mailsearch
```

## Командное демо на GitHub Pages

[Командное демо](https://ssd2008.github.io/HackFPMI-demo/) читает API на Mac через HTTPS-туннель. Отдельная копия `~/HackFPMI-preview` обслуживает демонстрацию из `main`. В рабочей копии агент может проверять незакоммиченные правки через `./run.sh --port 8766`. Публичный API при запуске проверяет контрольную сумму исходного синтетического корпуса VK.

### Настройка Mac один раз

На Mac с Apple Silicon и macOS 14+ нужен Homebrew, доступ к приватному `HackFPMI` и право Write в `HackFPMI-demo`. Для коммитов Pages настройте в Git имя и подтверждённый на GitHub адрес почты.

```sh
brew install gh uv tmux cloudflared
gh auth login --hostname github.com --git-protocol https
gh auth setup-git
git clone https://github.com/ssd2008/HackFPMI.git ~/HackFPMI-preview
tmux new-session -d -s hackfpmi-tunnel 'cloudflared tunnel --url http://127.0.0.1:8765'
tmux capture-pane -pt hackfpmi-tunnel -S -80
```

`tmux` (terminal multiplexer) держит процессы в отдельных сессиях после закрытия терминала. Возьмите из вывода `cloudflared` HTTPS-адрес и подставьте его при первом деплое. Если порт 8765 занимает старый ручной запуск, сначала остановите его.

```sh
~/HackFPMI-preview/scripts/deploy_preview.sh --api-origin https://ВАШ-АДРЕС.trycloudflare.com
```

На первом запуске будут скачаны модели и построен индекс. Журнал сервера находится в `~/HackFPMI-preview/.cache/preview-backend.log`.

### После изменений в `main`

```sh
~/HackFPMI-preview/scripts/deploy_preview.sh
```

Команда подтягивает `main`, при изменении бэкенда перезапускает API и дожидается ответа от него. Затем она публикует закоммиченные файлы интерфейса из `static/` в [HackFPMI-demo](https://github.com/ssd2008/HackFPMI-demo). При обновлении интерфейса адрес API сохраняется. GitHub Pages публикует коммит из `main` репозитория демо.

```sh
git -C ~/HackFPMI-preview rev-parse HEAD
curl -fsS https://ssd2008.github.io/HackFPMI-demo/version.txt
```

Идентификаторы должны совпасть после завершения [деплоя Pages](https://github.com/ssd2008/HackFPMI-demo/actions). Откройте демо, выполните поиск и откройте письмо. После перезапуска Quick Tunnel получит новый адрес. Повторите команду с `--api-origin`, чтобы его обновить. Держите Mac включённым и подключённым к сети. Для стабильного адреса можно использовать [именованный Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/get-started/).

## Что показать на демо

1. Откройте ящик 10. Кнопка **Сумма заказа** подставляет запрос «Какова сумма заказа SYN-077f40913b?» и дату 19 декабря 2027 года. Нажмите **Получить ответ**. Письмо содержит сумму **431,03 рубля**. Ссылка **[1]** откроет оригинал с номером заказа и суммой. Это отдельный пример работы RAG, которого нет в публичных запросах. [Пример ответа в интерфейсе](results/demo.jpg)
2. Для того же заказа можно задать собственный вопрос «В какой срок отгрузить заказ SYN-077f40913b?». В оригинале и в проверенном ответе модели указан срок **19 декабря 2027 года, 18:00**. Затем выберите **Заказы за вчера**. Дата запроса станет 19 декабря 2028 года. Выдача покажет новый заказ, полученный 18 декабря. Изменение даты в верхней части страницы меняет точку отсчёта для слова «вчера».
3. В ящике 02 установите 10 октября 2028 года и введите «Какие квитанции за коммуналку пришли вчера?». Прототип возвращает семь писем от 9 октября. Среди первых результатов — чеки за коммунальные услуги.

## Что требуют организаторы

Основной результат — веб-сервис для просмотра почты и поиска, который позволяет найти нужное письмо без знания точной формулировки. Команда выбирает сценарии и обосновывает их. Для защиты нужны исходный код, инструкция запуска, рабочая демонстрация и объяснение решения. Localhost подходит. Публикация в интернете даёт дополнительный балл. Ответы по письмам выбраны как дополнительная функция по запросу пользователя. [Исходная постановка](data/vk-mail-search.pdf)

Требование к скорости — **p99 строго меньше 1000 мс** от получения запроса сервером до готовой выдачи. Время включает разбор запроса, извлечение кандидатов и ранжирование. Сеть до браузера и отрисовка исключены. За превышение предусмотрен штраф. На этапах поиска и повторного ранжирования также предусмотрен штраф за использование модельных API или моделей более 3 млрд параметров. Ограничение относится к поисковому движку. Окончательные правила нагрузки, прогрева, кэширования и официальные метрики определяют организаторы. [Условие](data/vk-mail-search.pdf)

## Данные и даты

Оригиналы всех шести приложенных файлов лежат в `data/`. Четыре контрольные суммы из манифеста сверены. При подготовке и оценке есть повторная проверка SHA-256. [Описание набора](data/README.md) · [Манифест](data/manifest.json)

| Файл | Содержание |
| --- | --- |
| `documents.jsonl` | 16 376 писем. Ключ `doc_id`, ящик `synthetic_user`, исходный текст `doc`, дата получения `doc_dt`. |
| `queries_dev.jsonl` | 99 публичных запросов по 7 ящикам. Ключ `query_id`, ящик, текст `query`, дата запроса `query_date`. |
| `qrels_dev.jsonl` | 565 связей `query_id` → `doc_id` с оценкой 1. В 42 запросах ровно одно размеченное письмо. |

Прототип показывает срез ящика на выбранную дату. Письмо с известной датой доступно начиная с этого дня. У 433 писем дата получения отсутствует. Такие письма доступны при обычном поиске, во входящих стоят после датированных писем и исключаются из поиска за конкретный период. «Полученные вчера» и календарные периоды задают фильтр по дате получения. Выражения вида «со сроком оплаты до 30.12.2028» или «с доставкой на 27.12.2028» обрабатываются как текстовые признаки письма. Стартовая дата соответствует последнему датированному письму выбранного ящика.

## Как устроен поиск и RAG

1. **Область поиска.** Выбираем письма нужного `synthetic_user`, полученные к дате запроса. Разбираем «вчера», «позавчера», явные даты, диапазоны и распространённые периоды. При запросе без темы, например «письма за вчера», сортируем по дате. Для ID письма, буквенно-цифрового артикула и адреса отправителя поддерживается точное совпадение. Для буквального поиска заключите фразу в `«…»` или `"…"`. В запросе `вчера «операция отклонена»` дата ограничивает выдачу, а фраза должна целиком встретиться в доступном письме.
2. **Лексический поиск.** Русский стеммер приводит словоформы к общей основе. BM25-подобная оценка учитывает редкость слов, длину письма, совпадения в теме и долю совпавших терминов. У часто встречающихся понятий есть общие признаки для синонимов. Для возможной опечатки в русском слове длиной от шести букв ищем единственное частое написание на расстоянии одной правки. Коды, имена с прописной буквы и фразы в кавычках сохраняются.
3. **Смысловой поиск.** Локальная `intfloat/multilingual-e5-small` (117,65 млн параметров) кодирует запросы и письма в нормированные векторы из 384 чисел. Энкодер видит до 120 токенов. Лексический индекс охватывает полный текст, включая хвосты длинных писем. Матрица эмбеддингов корпуса занимает около 24 МиБ и переиспользуется между запусками. Запросы кодирует INT8-версия той же модели в ONNX Runtime на CPU. Независимые запросы могут кодироваться одновременно. Каждый вектор запроса вычисляется при обращении.
4. **Выдача.** Вес лексической оценки зависит от доли терминов, найденных в доступных письмах. Для первых кандидатов важна и близость поисковых слов внутри одного предложения. Отрицание исхода операции обрабатывается при индексации писем и разборе запроса. Незнакомые уточнения в запросах о заказе или счёте снижают вероятность совпадения с посторонней покупкой. Точные идентификаторы проверяются в пределах допустимого ящика и даты.
5. **Ответ.** По отдельному запросу сервер повторяет поиск в том же срезе ящика и передаёт до трёх подходящих писем из первых пяти в локальную `Qwen2.5-1.5B-Instruct`. Модель получает отдельный фрагмент на письмо. Сервер проверяет сгенерированную фразу по тексту и привязывает её к исходному `doc_id`. Есть проверки чисел, кодов и статусов. Если ответ не проходит проверку или модель занята, интерфейс может показать явно помеченные дословные выдержки. При недостатке сведений отображается соответствующее сообщение. Модель загружается при первом запросе ответа. Пользователь получает поисковую выдачу до генерации.

Сервис читает только корпус писем. Подсказки в интерфейсе строятся из текстов ящика. Публичные запросы и разметку читает отдельный скрипт оценки. Закреплённые ревизии обеих моделей находятся в [mailsearch/__init__.py](mailsearch/__init__.py).

## Проверка

Эти команды запускаются во втором терминале, пока почта открыта на порту 8765.

```sh
.venv/bin/python benchmark.py --k 1 5 10 --repeats 5 --output results/public_dev.json
.venv/bin/python benchmark.py --k 10 --repeats 5 --concurrency 8 --output results/public_dev_8_clients.json
.venv/bin/python benchmark.py --queries tests/fixtures/queries_paraphrased.jsonl --k 1 5 10 20 50 --repeats 1
.venv/bin/python benchmark.py --queries tests/fixtures/queries_typos.jsonl --k 1 5 10 20 50 --repeats 1
.venv/bin/python benchmark.py --queries tests/fixtures/queries_no_date.jsonl --unjudged --k 10 --concurrency 8 --repeats 5
.venv/bin/python tools/check_search_probes.py
.venv/bin/python tools/check_search_probes.py --fixture tests/fixtures/search_probes_extra.json
.venv/bin/python -m unittest discover -s tests -v
```

`benchmark.py` отправляет запросы по HTTP на тот же `/api/search`, что и браузер. Скрипт проверяет связи разметки, уникальность выдачи, владельца каждого письма и его доступность на дату запроса. Качество считается по первому проходу. Recall и nDCG усредняются по 99 запросам, MRR — по 42 запросам с одним релевантным письмом. При подсчёте метрик письма без разметки получают оценку 0.

Для измерения времени используется уже подготовленный сервер. Порядок запросов перемешивается воспроизводимо. В каждом из пяти проходов по 99 запросов. Серверный таймер включает чтение тела HTTP-запроса приложением, обработку, ожидание свободного обработчика и сериализацию выдачи. Клиент отдельно измеряет полный HTTP-запрос через loopback. p99 считается методом ближайшего ранга. Готовые выдачи и эмбеддинги запросов между запросами не кэшируются. Качество ответов генератора проверяется на отдельных примерах с оригиналами писем.

### Другой корпус или новые тесты

Поместите новый `documents.jsonl` в отдельный каталог. Чтобы сравнивать два сервиса, второму можно выделить отдельный порт.

```sh
./run.sh --data /path/to/new-data --port 8766
```

Для набора с `queries_dev.jsonl` и `qrels_dev.jsonl` запустите оценку во втором терминале. При наличии `manifest.json` проверяются контрольные суммы. До первого запроса клиент сверяет SHA-256 корпуса с работающим сервером.

```sh
.venv/bin/python benchmark.py --data /path/to/new-data --url http://127.0.0.1:8766 --output results/new-data.json
```

Для новых тестов на существующем корпусе передайте пути к `--queries` и `--qrels`. Если даны только вопросы, флаг `--unjudged` сохранит выдачи и задержки. При отсутствии `qrels_dev.jsonl` режим без разметки выбирается автоматически. Recall и nDCG считаются только для запросов с хотя бы одним размеченным релевантным письмом. Число таких запросов выводится в отчёте. Одного файла писем достаточно для просмотра и интерактивного поиска.

Для двух дополнительных файлов из командного репозитория есть локальный импорт. Файл с полями проекта сохраняет исходные байты, идентификаторы писем и ящики. У Gmail-экспорта конвертер назначает стабильные идентификаторы, а метки времени переводит в календарные даты указанного часового пояса.

```sh
.venv/bin/python tools/import_mail_export.py data/Sergey-mails.jsonl .cache/export-eval/corpus --mailbox-key independent-export-01 --timezone Europe/Moscow
.venv/bin/python tools/import_mail_export.py data/Kirill-mails.jsonl .cache/export-eval-02/corpus
./run.sh --data .cache/export-eval-02/corpus --port 8766
```

### Программный доступ

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/mailboxes` | Список ящиков, даты и примеры. |
| `GET /api/inbox?mailbox=…&date=YYYY-MM-DD&offset=0&limit=25` | Страница входящих на заданный день. |
| `GET /api/mail/{doc_id}?mailbox=…&date=YYYY-MM-DD` | Оригинал письма. Недоступное по ящику или дате письмо даёт 404. |
| `POST /api/search` | JSON с полями `mailbox`, `date`, `query`, `limit` от 1 до 100. В ответе ранжированный список `items`. |
| `POST /api/answer` | Те же ящик, дата и запрос. В ответе `answer`, упорядоченные `sources`, а также `mode` со значением `generative`, `extractive` или `no_evidence`. |
