Для первого сравнения двух версий поиска откройте [четыре почтовые выборки по 250 запросов](panels/). Каждая содержит 100 поисков конкретного письма, 100 подборок и 50 заведомо пустых запросов. Для проверки на миллионах исходных текстов уже готовы [первая часть](external/part-1/README.md) и [вторая часть](external/part-2/). Всего 7 936 основных задач и 7 034 переформулировки. У 4 170 основных задач одно целевое письмо, у 2 115 их несколько, у 1 651 ответ заведомо пуст. Для каждой части индексируется весь соответствующий корпус. В корпусе VK 16 376 документов. В личном 9 366 писем, из них 5 939 Сергея, 2 467 из Gmail Кирилла и 960 из частичной выгрузки Яндекса. Ящики одного человека отложены вместе. Запросы, их варианты и положительные документы разработки и финальной проверки не пересекаются в пределах одного источника. Из целевых документов исключены публичные ответы и документы, использованные в предыдущих командных тестах. Команда уже работала с этими ящиками, поэтому почтовый результат характеризует перенос на новые запросы и отложенных владельцев в этих корпусах.

Имена отправителей, темы, номера, даты и пустые ответы для точных правил проверены по полному ящику. У 950 смысловых задач эталон составлен по правилам и может пропускать подходящие письма. Для 59 задач ассистент отдельно проверил все письма в выбранном дневном окне. Независимой экспертной разметки владельцами у этого пула пока нет. Разметка различает прямой ответ (2), полезный контекст (1) и отдельно просмотренный нерелевантный документ (0). У каждого запроса есть сведения о происхождении разметки в файле cases.jsonl. [Проверка целостности и разделения](method/verify_suite.py)

На исходном dev организаторов у 49 из 99 запросов фильтр по ящику и дню уже даёт весь эталонный ответ. Поэтому отдельно подготовлены 56 пар запросов, в которых изменение одного условия меняет правильный ответ. 32 пары проверяют отсутствие даты получения, 24 различают возможную и уже произошедшую отмену заказа. Ещё для 388 почтовых запросов подготовлены проверки ответа со ссылкой на письмо. В 308 случаях есть проверяемый факт, в 80 ожидается сообщение о нехватке сведений. ## Запуск из рабочей копии проекта

Для почтового прогона нужен сервер команды с параметром --data и проверкой контрольной суммы корпуса. Проверена версия 7897913 ветки search/robust-ranking. В первом терминале из корня репозитория запустите локальную копию с выбранным набором.

```sh
POOL="$HOME/Downloads/HackFPMI-mail-OOD"
.venv/bin/python -m mailsearch --data "$POOL/suite/personal_dev" --port 8766
```

Во втором терминале из той же рабочей копии запустите короткий почтовый тест. Для полного прогона удалите параметр --panel вместе с его значением. Для проверки формулировок добавьте --variants. Параметр --output задаёт каталог для результатов конкретной версии.

```sh
POOL="$HOME/Downloads/HackFPMI-mail-OOD"
.venv/bin/python "$POOL/method/run_pool.py" --project "$PWD" \
  --suite "$POOL/suite/personal_dev" --url http://127.0.0.1:8766 \
  --panel "$POOL/panels/personal_dev.jsonl" --output "$POOL/runs/personal-v1"
```

Для сравнения двух вариантов поиска на одном пуле используйте tools/validate_rankings.py из командной ветки search/robust-ranking. Он принимает два rankings.json через --before и --after, а также queries.jsonl, qrels.jsonl и tasks.jsonl из каталога прогона через --queries, --qrels и --tasks. Итог пишется по пути --output. Парные доверительные интервалы вычисляются по семействам задач. Для одного владельца интервал по запросам не оценивает разброс между людьми. Финальные ящики сохранены здесь для проверки после выбора модели.

## Файлы и происхождение

В каждом почтовом наборе documents.jsonl содержит письма, queries_dev.jsonl и qrels_dev.jsonl содержат запросы с ответом и оценки. У пустых запросов и вариантов свои пары файлов с суффиксами empty и variants. Корпуса внутри почтовых выборок используют одни и те же байты через жёсткие ссылки. [Скрипт сборки](method/build_suite.py) · [Командные данные и оценки с привязкой к коммитам](github/inventory.json)

Скрипт и список больших наборов находятся в основной ветке приватного репозитория. Ветка datasets существовала отдельно, а актуальный перечень вошёл в main. Все девять источников из скрипта скачаны. Из внешних коллекций настоящую корпоративную переписку содержит Enron. Остальные состоят из вопросов, энциклопедических и веб-текстов, форумов и аннотаций научных работ.
