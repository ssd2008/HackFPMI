# Проверка поиска по почте

В наборе 4 149 основных задач для разработки и 3 754 дополнительных формулировок. Корпус VK и личные ящики оцениваются отдельно. Единица подсчёта — запрос к конкретному ящику на заданную дату. Варианты одной задачи вынесены в отдельный файл.

| Открытая часть | Задачи с ответом | Проверенные пустые | Письма для индекса |
| --- | ---: | ---: | ---: |
| `vk_dev` | 1 471 | 711 | 16 376 |
| `personal_dev` | 1 815 | 152 | 9 366 |

В каждом каталоге `suite` лежат стандартные `queries_dev.jsonl` и `qrels_dev.jsonl` с исходной четырёхпольной схемой для запросов и трёхпольной для разметки. Состояние запроса, семейство и допустимые цели сохранены в `cases.jsonl`. Пустые задачи и перефразы имеют отдельные файлы. Оценка 2 указывает прямое совпадение, 1 — полезное свидетельство из той же ситуации, 0 — проверенную ошибку. Отсутствие ряда в qrels означает, что эта пара отдельно не оценена.

**Для быстрого сравнения** в `panels/` зафиксированы две выборки по 250 задач. В каждой по 100 поисков конкретного письма, 100 подборок и 50 запросов с пустым ответом. Файлы `rag/` содержат эталонные факты, номера писем и признаки для проверки ответа. В `review_queue.jsonl` находится выборка смысловых запросов для дополнительной сверки человеком.

## Запуск

Подготовка работает из корня клона, где доступны обе командные выгрузки в `data/`. Она собирает документы из тех же файлов и сверяет SHA-256. Для запуска сервера и оценки нужна версия поиска с параметром `--data` и проверкой корпуса в `benchmark.py`. Подходит `search/robust-ranking` с коммита `7897913`. При использовании разных копий укажите путь к папке валидации и путь к рабочей копии поискового проекта.

```sh
POOL="$PWD/validation/mail-ood-v1"
python3 "$POOL/method/prepare.py" --data "$PWD/data"
python3 "$POOL/method/verify_suite.py"
.venv/bin/python -m mailsearch --data "$POOL/suite/personal_dev" --port 8766
```

Во втором терминале из корня проекта:

```sh
POOL="$PWD/validation/mail-ood-v1"
.venv/bin/python "$POOL/method/run_pool.py" \
  --project "$PWD" --suite "$POOL/suite/personal_dev" \
  --url http://127.0.0.1:8766 --output "$POOL/reports/personal"
```

Флаг `--panel "$POOL/panels/personal_dev.jsonl"` выбирает короткий прогон. Флаг `--variants` добавляет перефразы и опечатки. Для проверки VK укажите `vk_dev` при запуске и сервера, и клиента. Файлы `rankings.json`, `queries.jsonl`, `qrels.jsonl` и `tasks.jsonl` в каталоге отчёта подходят для парного сравнения двух версий через `tools/validate_rankings.py`, когда этот инструмент установлен в рабочей копии проекта.

## Как читать результат

Смотрите nDCG@10 и Recall@10 по каждому источнику и типу запроса. Для поиска конкретного письма есть MRR@10 и попадание на первое место. У запросов с подтверждённым пустым ответом отдельно считается доля ложных находок. Отчёт также считает выход за запрошенный интервал получения. Точные темы, номера и временные ограничения имеют проверяемый эталон. В смысловых задачах с пометкой `semantic_silver` категории определены правилами и допускают неполноту оценок.

Открытый личный набор проверяет задачи Сергея. Оба ящика Кирилла зарезервированы вместе для финальной проверки. В VK для неё отложены пять целых ящиков. Набор финальных запросов и оценок хранится отдельно у автора. Ранние ручные проверки команды уже использовали эти коллекции. Это проверка новых задач на знакомых источниках.
