# Локальный бенчмарк поиска по почте

Команды запускаются из корня проекта. Данные лежат в `data/`, зависимости установлены в `.venv`. Бенчмарк сверяет контрольные суммы трёх JSONL-файлов с `manifest.json` и использует уже построенный индекс E5 из `.cache/mailsearch`.

## Запуск

```bash
# Все локальные варианты ранжирования
.venv/bin/python -m search_bench --output search_bench/results/dev.json

# Быстрое сравнение без загрузки модели
.venv/bin/python -m search_bench --methods bm25 bm25-date char-date --repeats 1

# Те же письма и оценки релевантности с перефразированными запросами
.venv/bin/python -m search_bench --rewrites search_bench/paraphrases.json \
  --output search_bench/results/paraphrases.json

# Текущий MVP через localhost. Сервер запускается командой ./run.sh
.venv/bin/python -m search_bench --api http://127.0.0.1:8765 \
  --output search_bench/results/mvp-dev.json

.venv/bin/python -m search_bench --api http://127.0.0.1:8765 \
  --rewrites search_bench/paraphrases.json --output search_bench/results/mvp-paraphrases.json
```

Для другого расположения файлов есть `--data-dir`. Флаг `--k 1 5 10 20 50` задаёт отсечки метрик и максимальный размер выдачи. Чтобы добавить вариант локального ранжирования, зарегистрируйте его в `METHODS` и подключите вычисление оценки в `Search.rank`. [Ранжирование](ranking.py)

На новом компьютере окружение создаётся через `uv venv --python 3.12 .venv`, затем `uv pip install --python .venv/bin/python -r requirements.txt`. Для полного прогона веса и индекс готовятся командой `.venv/bin/python -m mailsearch.prepare`.

## Результаты

| Вариант | nDCG@10 dev | Recall@10 dev | nDCG@10 перефразы |
| --- | ---: | ---: | ---: |
| Только день получения | 0,6633 | 0,6559 | 0,6633 |
| BM25 без фильтра по запрошенному дню | 0,1604 | 0,2624 | 0,0835 |
| BM25 с датой | 0,9249 | 0,8765 | 0,7487 |
| BM25 с датой и весом темы | 0,9146 | 0,8754 | 0,7533 |
| **Символьные n-граммы TF-IDF с датой** | 0,9827 | 0,9312 | 0,8082 |
| BM25 с темой + n-граммы | 0,9677 | 0,9195 | 0,8086 |
| **E5 с датой** | 0,9352 | 0,8873 | **0,8825** |
| BM25 с темой + E5 | 0,9527 | 0,8993 | 0,8742 |
| n-граммы + E5 | 0,9690 | 0,9151 | 0,8574 |
| BM25 с темой + n-граммы + E5 | 0,9654 | 0,9132 | 0,8462 |
| **Текущий MVP через `/api/search`** | **0,9928** | **0,9376** | 0,8139 |

Фильтр даты сохранил 565 из 565 релевантных пар и сократил медиану кандидатов с 539 до 7. Текущий MVP достиг потолка Recall@10 на dev. Символьные n-граммы дали лучший результат среди проверенных самостоятельных вариантов на исходных формулировках, а E5 лучше всего справился с перефразированием. Простой гибрид через сумму обратных рангов оказался между ними по качеству.

На Apple M5 Pro p99 ранжирования у символьных n-грамм составил 0,89 мс, у E5 4,71 мс. У MVP p99 бэкенда составил 5,47 мс по заголовку `Server-Timing`, p99 запроса с клиента на localhost составил 6,12 мс.

Полные выдачи и метрики по каждому запросу сохранены в JSON. [Dev](results/dev.json) · [Перефразы](results/paraphrases.json) · [MVP на dev](results/mvp-dev.json) · [MVP на перефразах](results/mvp-paraphrases.json)

## Методика

- 16 376 писем, 12 ящиков, 99 запросов, 565 положительных пар. Во всех вариантах действует ограничение по ящику и дате запроса. При явном периоде точная фильтрация использует `doc_dt` и исключает письма с неизвестной датой. Обе версии BM25 получают один и тот же текст запроса после извлечения даты.
- Метрики усреднены по запросам. MRR@K посчитан для 42 запросов с одним релевантным письмом. Порог K ограничивает максимально возможный Recall, на K=10 потолок равен 0,9376.
- Для проверки перефразирования вручную заменены 12 повторяющихся формулировок темы. Даты, ID запросов и размеченные письма совпадают с dev. Все 99 запросов в обеих версиях указывают конкретный день получения. [Замены формулировок](paraphrases.json)
- Время измерено на прогретом процессе по 297 последовательным вызовам на метод, с выдачей до 50 писем. Подготовка индексов измеряется отдельно. Запросы и выдача не кэшируются бенчмарком. Замер MVP охватывает поисковую выдачу, генерация ответа идёт через отдельный маршрут. Нагрузку и правила замера закрытого теста определяют организаторы. [Условие](../data/vk-mail-search.pdf)
